## Pourquoi les agents de codage IA ont besoin de mémoire

Les agents de codage IA comme Claude, Cursor et OpenCode sont puissants — mais ils ont une limitation critique : **pas de mémoire entre les sessions**.

Chaque fois que vous démarrez une nouvelle session, votre agent :

- Oublie les décisions d'architecture d'hier
- Ne se souvient pas des correctifs de bugs que vous avez découverts
- Ne peut pas rappeler les patterns que votre équipe a établis
- Doit réapprendre votre projet depuis zéro

Cela gaspille des tokens, du temps et mène à une répétition frustrante.

## La solution : mémoire persistante pour les agents IA

**toon-memory** donne à votre agent de codage IA une mémoire persistante qui :

1. **Survit aux redémarrages** — la mémoire persiste entre les sessions
2. **Fonctionne hors ligne** — pas de cloud, pas d'appels API, pas de LLM nécessaire
3. **Économise des tokens** — 22% de tokens en moins que le JSON
4. **Évolue** — 80% d'appels d'outils en moins par session
5. **Fonctionne partout** — 15+ agents supportés

## Que peuvent retenir les agents IA ?

### Décisions
```bash
memory_remember({
  category: "decision",
  key: "use-zod",
  content: "Use Zod for validation — simpler than Joi, better TS support"
})
```

### Correctifs de bugs
```bash
memory_remember({
  category: "bug",
  key: "redis-pool-fix",
  content: "Redis pool exhaustion — fix was max_connections=20"
})
```

### Patterns
```bash
memory_remember({
  category: "pattern",
  key: "api-versioning",
  content: "Always use /api/v1/ prefix for REST endpoints"
})
```

### Connaissances
```bash
memory_remember({
  category: "knowledge",
  key: "deploy-process",
  content: "Deploy script lives in scripts/deploy.sh, runs on CI merge to main"
})
```

## Fonctionnalités mémoire

- **34 outils MCP** — remember, recall, forget, stats, summary, archive, diff, suggest, smart_recall, encrypt, decrypt et plus
- **Rappel conscient du graphe** — connecte les entrées liées avec des liens et références
- **Score de qualité** — note automatiquement la qualité des entrées (0-1)
- **Fusion-dédup** — enregistre avec la même clé, fusionne automatiquement
- **TTL** — les entrées peuvent expirer après 7j, 30j ou des dates personnalisées
- **Chiffrement** — AES-256-GCM pour les données sensibles
